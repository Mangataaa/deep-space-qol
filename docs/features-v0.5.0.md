# 0.5.0 功能与验证范围

本轮基于本机 0.46 系列程序集开发，经用户复测反馈后作为公开测试版发布。新功能的离线规则验证与用户实机截图分开记录；未宣称完整周目或全部模组兼容。用户反馈与截图边界见 `runtime-validation-v0.5.0.md`。

## 悬挂与操作提示

- 用户截图中的日历位于场景约 19%–32% 宽度。左侧挂件区现在止于 18.5%，右侧挂件区位于 70%–92%；均限制在屏幕顶部区域，保持原图比例，不改变实际物品形状和保存位置。
- “请先结束拖拽、多选或固定模式”是旧的通用自动操作保护提示。现在分别说明阻止原因；只打开悬挂管理窗允许固定模式，真实自动转移仍保留限制。
- 管理窗下方增加原生独立勾选控件。界面堆栈只包装渲染元素，原生窗口仍链接同一个储物 Grid；保存路径沿用既有展示柜转换。

## 每日普通顾客

- 配置 `daily_expected_visitors` 默认关闭，在悬挂管理窗或游戏设置切换。修改配置不会重新生成当前队列，只在下一次原生日排程时读取。
- 原方法 `StoreClientManager.HandleNormalClient` 在成功来源达到基础名额后提前退出来源循环。补丁只替换这一处配额判断，让所有原生有效来源各执行一次原概率判定；不改原概率、来源工厂、来源 ID、保底回调和随机补足。
- 基础名额由原版计算，并非硬编码 4。保留同名去重、通缉占位、教程等约束，因此 13 项来源不保证 13 位客户，也不能无条件承诺 4 位最低数。
- 客流面板在开启时将原数字标记为基础名额，并追加说明。只读原生已经渲染的标题，不额外调用会消耗 RNG 或初始化选择缓存的预测接口。
- 原生 IL 锚点不匹配时整段保留原版并记录警告，管理窗提示开关未生效。

## 一键改装

- 入口在枪械委托交易面板的交付按钮左侧，采用游戏自带按钮。只处理原生 `ResolveOrderGun()` 返回的当前委托枪。
- 仅扫描自有、未固定、未锁定、无剧情保护的散装库存配件。机器、其他枪内部、非自有交易物品不作为配件来源；允许保留客户自带原件，不能任意拆走。
- 按原生枪况加成、基础和百分比属性、消音等级、口径、尺寸及严格条件边界建模。先完整满足必需条件，再搜索附加奖励；有时间和节点预算，不承诺全局最优。
- 搜索与旧件空位预检分帧，在原生主线程运行。提交前复核当前委托、身份、属性、形状、锁定与位置。旧件必须预留安全空位，再经原生槽位移动；原生最终验证失败尝试恢复。
- 不创建配件，不伪造达标状态，不自动修复枪况，也不调用交付操作。完成后由玩家检查并确认。

## 验证与用户复测

自动检查包含悬挂几何避让、真实日排程 IL 的离线受控执行、枪械组合及真实原生规则回归，共 17 套测试与原生扫描通过。开发记录位于本地忽略的 `artifacts/0.5.0-audit/`。开发代理本轮未启动游戏或改写私人存档；随后用户自行复测并提供五张截图及“大致没问题”的反馈，具体范围见 `runtime-validation-v0.5.0.md`。离线检查不能替代全部 Unity 运行组合。

建议用户按以下顺序复测：

1. 固定模式下点击“悬挂”，确认可打开、灯牌不挡日期，勾选状态能持久保存。
2. 勾选后自然推进到下一天，确认原挂牌概率来源均能参与，今天的队列不突变；关闭后再推进一天确认恢复原版。
3. 枪械委托放好枪，备齐散件后点“一键改装”，核对必需／附加条件、旧件数量和实际交付；锁住候选配件或腾空仓库时应明确提示。
4. 大量配件搜索中按 Esc 或切换相关库存，确认无未提交的物品移动；保存退出再载入核对正常。

保留安装前模组备份。玩家私人存档、游戏程序集、反编译源码及本地审计产物不包含在发布包内。
