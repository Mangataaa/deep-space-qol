# 0.4.1：悬挂管理、暗灯桌面与分帧收纳

日期：2026-11-14。本轮为本地复测版，不复用旧版实机通过结论。

## 依据和范围

沿用本机 0.46 程序集（SHA-256 `725cb999d019dff1ff31bed353c7f9bb8d81a7605a15de1f80f5a3a6cf7b1d05`）及此前缓存的反编译结果。本轮 REA CLI 静态身份检查记录 `ev_e9976a693be02a1c8c8375dd04c8672c58cc0c127d008d201a3e83f1d3f3abe8`，原始离线输出在忽略的本地审计目录；该检查没有执行游戏，不是运行时证据。

原生 `PixelWindow` 支持 `Show` / `Hide` / 关闭回调 / 可移动机械窗口；`GameGridInventory.SetTransparency(1)` 保留原生接收物品的区域但透明绘制，`HideBorder` 去除边线。放置坐标由原生 `InverseTransformPoint` 从真实网格变换读取。`BlackLampHelper` 的目标、图案和引流概率仍使用原生路径。

## 悬挂的真实物品和装饰投影

- 继续使用 0.4.0 的 24×4 原生管理库存、物品实例、区域标签及保存编码，不换容器身份。
- 展示柜旁一个“悬挂”按钮打开可关闭管理窗。支持原生拖放，按钮“移入”批量移动原柜适用物品，“取下”返回原柜，“完成”关闭。固定物品的原生限制保留。
- 平时隐藏管理窗，另以真实物品的现有 `background.image.sprite` 和激活的原生装饰图层生成纯图片投影。投影没有 GameItem、存档 ID、复制库存、拖放逻辑或效果。点击投影仅重新打开管理窗。
- 投影在上方左右两组布局，中心卷帘区域不占用；有双吊线、挂点、接触阴影，灯牌保留原生图案／发光层。按画面与数量等比适配的是图片；绝不累乘真实物品的 transform 或改变其 shape。管理窗内仍用原物品的原生点击区域。
- 关闭、按 Esc 或其他原生关窗路径后，下一次低频刷新回到悬挂展示；离店隐藏，载档／停用清理自己的节点。

## 暗灯桌面

原 4×6 竖排区换为 8×3 横排透明原生网格，位于参考图圈选的右侧桌面（录音机左侧、主库存上方），不绘制标题、边框或网格。不是另画一个不可操作的暗灯图标；玩家仍操作真实暗灯的原生元素，右键切换目标和固定照常。独立的非交互椭圆阴影只增加桌面接触感。

旧版读档先尝试精确布局；竖排坐标不适用时，在新区域寻找保留原朝向的完整位置，含已固定灯。区域满或布局损坏时留在原生展示柜并记日志，不删除或复制。两区效果合并和原生保存编码延用 0.4.0。

## 收纳卡顿路径与修复

旧 UI 同步执行一整轮 `StowService.Run`，最多 2.5 秒；每个目标页的摆放搜索又最多 220 毫秒。现在所有 UI、快捷键及高级面板调用 `Start`，使用原生模组协程逐帧执行：扫描、试放、几何搜索和页间处理均可让出主线程，目标每片约 3 毫秒。摆放搜索的 220 毫秒 CPU 预算不包括等待帧的时间，无整轮两秒弃置。

所有游戏／Unity API 都在主线程，不引入任务线程。搜索期间不临时移出物品；完整布局通过原生校验、身份／数量／状态快照、当前锁定和固定权限复核后才原子提交，失败恢复原位置。一次原生移动及整页提交不可再分片，因此 3 毫秒是调度目标，不是绝对帧时上限。

跨帧期间重新读取页分类和锁，取消、拖拽、固定模式、离店、换档或停用会停止；已经完整完成的移动保留，待提交方案不应用。其他一键动作通过共同入口等待，重复点击显示当前进度。界面显示进度并可按 Esc 取消。

## 检查与待复测

- 多分辨率、0–96 挂件、图片不重叠、中心留空、等比缩放、重复刷新稳定性和暗灯桌面范围检查；沿用真实 `SaveManager.EncodeNodes` 的原生保存关联与布局往返检查。
- 增量摆放与同步算法在相同节点预算下比较，检查完整几何、原生否决、取消不提交、CPU 预算不计帧间等待、原生谓词仍在调用线程。
- 收纳增量夹具使用 1,200 件原生数据对象执行真实目录、规则、扫描和调度，最终渲染整理使用替身；覆盖扫描让帧、全数归位、新分类／页锁／箱锁、来源变更及取消。此测试不执行真实 Unity 拖放和保存。
- 全套构建、测试和原生扫描结果保存在本地 package.log。没有把离线检查写成游戏实测。

用户实测优先：管理窗放入／关闭／重新打开；挂件是否挡时钟、日历、客户或原生按钮；不同 UI 缩放；暗灯三种目标切换及拿起／放回；旧 0.4.0 存档灯数是否完整；多箱大库存收纳时的帧流畅度、取消后继续；保存→完全退出→重载后的物品数量、位置、固定状态与原有效果。
