# 0.4.0：浮动窗口、真伪检查和独立陈列区

日期：2026-11-14。依据本机合法安装的 `Assembly-CSharp.dll`，SHA-256：`725cb999d019dff1ff31bed353c7f9bb8d81a7605a15de1f80f5a3a6cf7b1d05`。以下区分源码／程序集离线检查和待进行的游戏内操作。

## 浮动窗口漏标

原生 `PixelWindow.EnsureFloatingDock()` 将可移动窗口的 RectTransform 移入 `LetterboxManager.DockRoot`。原实现仅递归 `RenderHandler.current.windowRoot`，因此交易台可见而箱内漏标。`VisibleItemViews` 现在合并主根和 `WindowsHandler.current.visibleWindows` 的实际可见窗口，去重、排除隐藏节点和调试目录，再由品质／搜查模块创建各自非交互标记。仅遍历已打开窗口，不自动开箱。窗口销毁、页签隐藏或渲染宿主改变时清理／重建绑定。

## 真伪鉴定

支持原生香烟、票券／邮票、注射器三个有真伪对质流程的检查页。检查现有 `modifiedState` 的原生问题标签，并核对 `CATEGORY_GENUINE_*` 特征；不通过颜色、售价或物品名称猜测真假，不创建缺失标签。

有问题时选中与原生理由一一对应的 Toggle，调用 `InspectionUIManager.OnConfront()`，由原生处理揭露、折价、声望、唯一剧情物品及对话。正品只提示。数据缺失、特征停用、已经对质、问题已公开、自有物品、物品不在当前顾客交易区或原生对质锁生效时，不发起对质。价格鉴定继续只填价，由玩家提交。

## 独立区域与效果

- 上方为 24×4 原生格子，接受明确核对的证书、营业许可、三级枪证和原生灯牌；暗灯为单独 4×6 区域。
- 暗灯区域优先靠录音机右侧放置；屏幕右侧不足时放到录音机下方的右侧边缘，避免遮挡其原生操作区。最终不同分辨率的观感待实测。
- 支持原生拖放、固定、取放和暗灯切换目标。批量“悬挂”只移动原生展示柜中自有、未固定且可完整移除的适用物品；“取下”在原生展示柜找空位，放不下原地保留。
- 原生效果读取 `showcaseElement.childItems`。补丁只给这个具体库存的返回列表加入两个区域中的真实物品并去重，其他库存不改。证书等级、许可吸引的客群、灯牌引流、暗灯数量与目标仍交给原生函数。
- `children` 保留两区的真实库存层次，以便原生的全店物品查找和保存。两区不重复注册为全局图根，避免重复搜索同一个库存。
- 不复制商品，不缩放真实图像，不分离图像与原生点击区域，不重新计算／覆盖其他模组的全店效果。此设计减少所参考模组评论涉及的问题路径，但不构成所有兼容组合无缺陷的保证。

## 保存与停用

不注册新的商品 ID，也不创建自定义保存文件。仍经原生 `showcase_save_bag` 和 `SaveManager.EncodeNodes` 编码真实物品。编码完成后只把两个运行时区域的库存索引映射到原有展示柜索引；普通商品、其他模组库存索引及商品内部库存关联不变。

区域和布局放在原生物品标签中。序列化副本使用原生展示柜范围内的坐标，真实区域坐标另存于可忽略的布局标签；正常加载模组后恢复到对应原生格。编码过程不搬动真实物品，不改变真实尺寸、旋转或翻转。无模组加载时无需解析任何新物品类型，满柜时可能出现重叠，可逐件移出。

**计划停用／卸载前，先腾出展示柜空间，点“取下”，确认两区已空后保存。** 运行中停用会尝试放回展示柜，再尝试主库存；两处均满时保留在原生展示柜内，可能重叠，绝不以腾空为由删除物品。损坏／不兼容的布局标记或位置冲突保留物品在原生柜中并记录提示，不猜测并强行丢弃。

## 验证范围

十三套离线测试；真伪判定 592 项。陈列区测试直接调用实际程序集的 `SaveManager.EncodeNodes`，检查原生链接映射、每件仅一次、嵌套库存不变、无模组坐标可见范围、精确布局恢复、保存不修改真实数据，以及损坏标记的拒绝路径。计数见构建日志。

本轮 `@oai/sky` 读取 Steam 窗口先后返回 `FrameArrived timed out` 和 `window capture timed out`，停止了实机操作尝试；未启动游戏，未载入／改写原存档，未修改云同步设置，未安装测试探针。已有存档／设置另行备份并核对原文件哈希。`BUILD-INFO.json` 的 `inGameTested` 为 `false`，历史 0.3.0 实机记录不能替代本版本验证。
