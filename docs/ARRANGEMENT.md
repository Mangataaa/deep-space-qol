# 0.2.3 整理算法

本项目独立实现，未复制第三方模组代码。开发中查阅过 Smart Inventory Arrange 的按类型分组、布局评分和有限搜索思路。两个参考仓库分别为 Nwflower/smart-inventory-arrange（FSL-1.1-MIT）和 xiepeixuan/SmartInventoryArrange（MIT）；本次仅参考方法，不引入其源码或许可。

旧版在逐物品、逐朝向扫描中共享很小的节点预算，容易在找到完整候选前耗尽。排序并不等于空间排布：同 ID 商品在读取顺序相邻，也可能在格子中散落。

新版先为同 ID、相同矩形轮廓的商品尝试多种行列块形，再对前几组做有限回溯，避免早期选定的块形堵死后续商品。不同实例仍独立保留各自的形状索引，并逐件检查原生位置谓词。不规则形状、特殊图层和无法成块的组继续走通用有限搜索。

候选评分依次重视同类实占格的连通区域、同类包围盒空隙、朝向一致性，以及整体空隙和靠左上紧凑程度。扩大了节点预算，并同时保留时间上限。固定物品、不可用格、图层碰撞和原生限制都属于硬约束。

始终保留完整原布局。候选缺件、重复、重叠、原生拒绝或未优于原方案时不应用；应用阶段仍核验身份、数量、状态和位置，异常时恢复。此算法不保证全局最优，也不会跨页、拆分、合并或变更物品状态。枪械整件参与排布，不重排其内部配件。

## 检查

`dotnet run --project tests/GridPacking.Tests.csproj -c Release` 覆盖同类成块、统一朝向、重复点击稳定性、混合尺寸、不规则格、图层、原生拒绝、耗尽回退和固定种子随机场景。

测试入口也可读取离线形状样本，验证完整性与质量；可选第二个参数输出排布结果。只读样本，不操作真实存档或运行 Unity 场景。个人存档和提取布局均保存在忽略的 `artifacts/`，不随源码或发布包上传。
