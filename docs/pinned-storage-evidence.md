# 固定储物容器内容访问修复（0.3.1）

日期：2026-11-13。目标程序集 SHA-256 为 `725cb999d019dff1ff31bed353c7f9bb8d81a7605a15de1f80f5a3a6cf7b1d05`。REA 静态身份记录为 `ev_e9976a693be02a1c8c8375dd04c8672c58cc0c127d008d201a3e83f1d3f3abe8`；完整记录保留在本机忽略的审计目录，不随源码分发。

## 根因证据

- 本机同哈希程序集的 ILSpy 辅助代码中，`ContainerHelper.InitContainerItem`、`InitSmugglerBay`、`InitBackpackItem` 也给普通容器添加 `IMPORTANT_TAG`；该标签并不表示其中每件商品都属于剧情。
- 只读检查玩家指定游戏的现有存档，确认普通固定大储物柜同时带 `IMPORTANT_TAG` 与 `PINNED_TAG`。检查没有写回存档，个人记录不上传。
- 0.3.0 的 `StorageCatalog.HasStorageIdentity` 排除了所有重要物品，`StorageRules.IsQuestInventory` 又阻止重要祖先容器的全部内容；普通柜体因此在两层被排除。固定只是该存档中同时存在的状态，取消固定不能解决泛化的重要标签误判。
- 旧离线夹具漏了普通柜体的原生重要标签。补齐夹具后，在修复前稳定失败于 `makeshift_storage_bay should expose its direct native storage grid`；两层修复后通过。

REA 记录用于程序集身份与范围核对；上述方法语义来自本机 ILSpy 辅助代码，行为验证来自真实程序集的数据夹具执行，不能混称为 REA 已观察到实机行为。

## 修复范围与保护

储物目录仍按现有严格 ID 白名单和真实窗口结构识别。普通重要容器的壳体与内容权限分开：壳体继续受原有不可移动／不可出售保护，已核对的自有普通储物页不因壳体的重要标签被整页排除。固定容器本体不取消固定，也不将固定标记传给内部商品。

卢的 ID 与 `LOU_TOY_TAG`、`LOU_TOY_BOX_TAG`、`LOU_LOCKER_TAG` 先于白名单判定，即使套用普通储物 ID 仍不开放。页锁、箱锁、祖先锁、原生库存／窗口／容器锁、商品自身固定／重要属性继续生效。未知重要容器和设备格不开放；非自有重要祖先也不享受例外。

回归覆盖普通箱包和柜体的固定／非固定组合、真实原生重要标签、三页柜、嵌套固定背包及上述保护反例，储物目录／收纳共 1168 项通过。十一套离线测试全部通过；本补丁没有执行新的游戏内上货操作，不能将 0.3.0 的受控 UI 结果外推为本次修复已实机验收。
